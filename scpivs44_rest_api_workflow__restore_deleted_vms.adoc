[.lead]
To perform restore operations for VM backups using the SnapCenter Plug-in for VMware vSphere REST APIs, you must follow the prescribed sequence of REST API calls.

For each REST API, add `\https://<server>:<port>` at the front of the REST API to form a complete endpoint.

|===
|Step |REST API |Comments

|1
|`POST /4.1/auth/login`
|Pass the vCenter credentials to get the token. Send the token in the `Token` header for all subsequent calls. If the username contains a domain, separate with \\.

|2
|Go to
`\http://<vCenter-IP>/mob` or use the vSphere Web Client to find the VM UUID.
|Find the moref of the datastore on which the deleted VM resided, for example, `datastore-238`.

|3
|`GET /4.1/datastores/{moref}/backups`
|Retrieve all backups for that datastore. Pass the datastore moref from Step 2. Note the ID of the backup you want to restore from.

|4
|`GET /4.1/backups/{backupId}`
|Retrieve backup details. Pass the *backupId* from Step 3. In the entities list, find the entry whose *entityName* matches the deleted VM and note its UUID.

|5
|`GET /4.1/vm/backups/{backupId}/snapshotlocations`
|Retrieve the snapshot locations for the backup. Pass the *backupId* from Step 3. Note the snapshotLocationsList entries (datastore, storage, volume, and locations). This endpoint takes only the backup ID, so it works for a deleted VM.

|6
|`GET /4.1/datastores/{moref}/availableEsxHosts`
|Retrieve the ESXi hosts available for the restore. Pass the datastore moref from Step 2. Note the host name. Do not use `/4.1/vm/{moref}/backups/availableesxhosts` here; it requires a VM moref that still exists in inventory.

|7
|`POST /4.1/vm/{uuid}/backups/{backupId}/restoreVm`
|Restores the deleted VM. Pass the *UUID* from Step 4 and the *backupId* from Step 3. Pass the Step 5 and Step 6 information in the `esxHost` and `restoreLocations` attributes. If the VM backup is a partial backup, set the `restartVM` parameter to *false*. 

*Note:* You cannot restore a VM that is a template.
|===
